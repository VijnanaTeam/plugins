# 钉钉

钉钉的所有操作都通过钉钉官方命令行工具 **`dws`**(DingTalk Workspace)完成。

## 怎么用(先查技能,再动手)

`dws` 自带成套官方技能文档,**不要凭记忆猜命令和参数**:

```bash
dws --help                  # 顶层能力总览
dws <domain> --help         # 某个业务域的命令与参数
```

标准流程:**先查该业务域的帮助/技能说明,看清参数与返回,再执行**。首次执行会自动安装 CLI(需等待片刻)。

业务域(`dws <domain>`):`chat` 群聊消息、`ding` DING 消息、`doc` 文档、`sheet` 表格、
`aitable` AI 表格、`wiki` 知识库、`drive` 钉盘、`calendar` 日历日程、`todo` 待办、
`contact` 通讯录、`attendance` 考勤、`minutes` AI 听记、`mail` 邮件、`oa` 审批、
`report` 日志、`whiteboard` 白板、`live` 直播、`aisearch` AI 搜问 等。

非交互场景加全局 `-y` 跳过确认提示;输出默认 JSON,可用 `--format`、`--fields`、`--jq` 裁剪。

## 授权

本部门首次使用钉钉时要授权一次,之后一直有效。命令是固定的两条,**照抄,不要自己找别的**:

```bash
dws auth status                        # 先看是否已登录
dws auth login --device --recommend    # 未登录才执行
```

- **`--device` 必须带**。这里是无头容器,默认登录方式会把回调指向 `127.0.0.1`,用户的浏览器
  根本到不了,授权完成也写不回 token。设备流才会打印用户能用的短链接 + 授权码。

> ⚠️ **`dws` 自带的官方技能文档里有这么两行,第一行在本环境里是坏的**:
>
> ```
> # 本机浏览器登录；无头环境使用 --device
> dws auth login --recommend --format json          ← 不要用这条
> dws auth login --device --recommend --format json ← 用这条
> ```
>
> 官方文档面向的是有浏览器的桌面环境,所以把不带 `--device` 的写在前面。**你运行在无头容器里**,
> 挑第一条的后果是:命令挂住几分钟等一个永远不会来的浏览器回调,然后失败,而你会误以为
> "已经打开浏览器页面了"去让用户扫码 —— 用户那边什么都没有。**任何时候执行 `dws auth login`,
> 都要带 `--device`。**
- **`--recommend` 免去逐项挑权限**,登录后自动授权服务端推荐的那批。
- **不要问用户"要授权哪些范围""有效期多久"**。钉钉这里是整账号 OAuth 登录,范围由 `--recommend`
  决定,没有"本次会话/一次性/永久"这种选项 —— 问了只会把用户绕晕。
- **`dws pat` 不是登录命令**(它是"行为授权管理",另一回事),别拿它当授权入口。
- 平台**没有**"连接器设置"之类的钉钉登录页面。授权只能在这里做,不要让用户去别处找。

把设备流打印的**链接和授权码**交给用户,请其用钉钉确认;完成后再继续原来的任务。
授权数据由平台统一管理,不要手动改动。

> **转述链接的硬性要求**:CLI 的输出里可能自带 `**` 之类的 markdown 标记。给用户的链接必须是**干净可点的纯 URL**
> —— 逐字复制 `http(s)://` 开头到第一个空白为止的部分,**去掉紧邻的 `*`、反引号、括号等装饰字符**,
> 也不要自己再包一层加粗。链接里多一个字符就会打不开(授权码同理,单独一行原样给出)。


## 约定

- 所有操作以**用户本人**的钉钉身份进行,受其自身权限范围约束。
- 写操作(发消息、改删文档、改日程、传文件等)执行前,先向用户确认目标与内容。
- 命令输出多为结构化数据,可直接解析后再做下一步;需要落地的文件用 CLI 提供的下载命令,不要手工拼 API。
- 遇到权限或授权错误:把 CLI 给出的原始提示与链接如实转达用户,不要反复重试或绕路。
