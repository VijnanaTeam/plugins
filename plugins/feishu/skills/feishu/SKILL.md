# 飞书

飞书的所有操作都通过命令行工具 **`lark-cli`** 完成(它是飞书官方 CLI,覆盖 11 个业务域、200+ 命令)。
**凭据已由平台按当前用户注入,不需要也不要执行任何登录/授权命令。**

## 怎么用(重要:先查技能,再动手)

`lark-cli` 自带成套的官方操作手册,**不要凭记忆猜命令和参数**:

```bash
lark-cli skills list                 # 列出所有业务域技能(im/docx/drive/base/sheets/wiki/calendar/task…)
lark-cli skills read <skill-name>    # 读某个技能的完整用法
lark-cli <domain> --help             # 查具体命令与参数
```

标准流程:**`skills list` 选中相关技能 → `skills read` 看清用法(含参数、返回、注意事项)→ 执行命令**。
技能文档里若引用了 `references/xxx.md`,继续用 `lark-cli skills read` 读它。

## 身份:user 还是 bot

飞书区分两种身份,同一个接口在两种身份下行为不同,**选错会失败或看不到数据**:

- `--as user`(用户身份):访问**用户自己**的资源——个人云盘文件、日历、文档、其参与的群。
- `--as bot`(应用/机器人身份):以机器人名义操作。**机器人只能看到自己所在的群**;要往某个群发消息,机器人得先在群里。

默认会自动选择。当结果为空或报权限错时,先想清楚"这个资源属于谁",再显式加 `--as` 重试。
**同一条工作流里,后续命令要沿用取得该 ID/Token 的那个身份。**

## 出错怎么办

- **权限不足**:错误里通常带 `missing_scopes`(缺哪些权限)和 `console_url`。**不要自己反复重试或绕路**,
  把缺的权限和链接如实告诉用户,让其在飞书开发者后台开通后重新授权。
- **未连接**:提示用户到「插件中心 → 飞书 → 连接」完成授权。
- **机器人不在群里**:可先将机器人拉入该群(需用户是群主/管理员),再发送;这属于改变群状态,**先征得用户同意**。

## 约定

- 所有操作以**用户本人**的飞书身份进行,受其自身权限范围约束。
- 写操作(发消息、改/删文档、删记录、拉人进群等)执行前,先向用户确认目标与内容。
- 命令输出多为 JSON,可直接解析后再做下一步;需要落地的文件用 CLI 提供的下载/导出命令,不要手工拼接 API 请求。
