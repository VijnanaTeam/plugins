# Technical Documentation

Produce a document that a new maintainer can implement or operate without hidden context.

1. Establish the audience, scope, and non-goals.
2. Describe the system boundary and the authoritative source of truth.
3. Specify inputs, outputs, state transitions, permissions, errors, and rollback behavior.
4. Include only examples that match the real implementation.
5. Record deployment and verification steps separately from the design.
6. End with unresolved decisions or operational risks; omit the section when none remain.
